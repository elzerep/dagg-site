# Implementation
Page title: The Dagg Factory

## H1
Nothing is built until the decision, the owner and the way back are explicit.

## Lead
The Dagg Factory is how a decision becomes something running in production. Its
discipline is at the door: what it declines, and on what grounds.

## What has to be true before a build starts

**The decision is written down.** Not the requirement — the decision. What is
changing, and what is deliberately not.

**Someone owns the outcome after launch.** Named, and aware they are named.

**The failure mode is understood.** What a wrong answer costs here, and who
finds out first.

**There is a way back.** A change that cannot be reversed is not a first
change. Where reversal is genuinely impossible — data written to a third party,
an action taken in the world — that is said before the work begins, not
discovered afterwards.

## Two modes

**Automate what should stay.** Work that is right, carried by people between
systems that do not speak. Agents take the carrying; the systems remain. Nobody
learns a new tool, because the work continues where it already lives.

**Rebuild what should change.** Where the workflow layer is what is broken, an
agent placed on top makes the wrong thing faster. Then it is new software, and
often one fewer system afterwards.

## The map the build reads

The WorkGraph is not documentation kept alongside the work. It is what the
build reads from.

The agents that write the software query it directly, so the structure of the
workflow — which systems hold what, where the handoffs are, which decisions
need a person — is available rather than restated. A model without it has to be
told all of that by someone who knows it, each time.

## Agents that can be trusted with the work

An agent acting inside a company needs three things first.

**Bounds**, expressed as what it may touch rather than as an instruction it is
asked to respect.

**Escalation**, with the cases it must hand back decided in advance rather than
discovered in production.

**A record** of what it did and on what basis, in a form somebody can read
months later when the question is why.

The third is usually treated as compliance overhead. It is what makes the first
two enforceable.

## Production and ownership

Work ships with monitoring, a named owner and a documented way back. That is
the end of the build. What follows is a choice worth making deliberately.

**You operate it.** This requires someone who can read the monitoring, respond
when an agent escalates, and judge when behaviour has drifted. We set that up
and hand it over, including what to watch and what should worry you.

**We operate it.** Where running agents is not a capability a company intends
to build, the operation can stay with us. The same WorkGraph orchestrates what
is live.

The software and the model of your company are yours either way, and that sits
in the agreement rather than in a conversation.
