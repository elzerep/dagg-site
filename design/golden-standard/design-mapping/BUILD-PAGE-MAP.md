**FS5 amendment.** Remove the cinematic hero image from the first screen. The
first proof is a coded 5/7 Factory stage showing Approved intervention,
Specification and permission, Evaluation, Review state and Evidence return for
WG-034. The page disclosure precedes it. The paragraph beginning `Dagg Factory

viewport or first Factory stage. B-OE-MS-01 is retired from production placement
and retained only as audit and development evidence. It must not be loaded on
Build or reassigned to another route. The asset files and hashes remain
preserved. This statement supersedes every contrary asset, composition and
acceptance instruction below.

Build is the page where Dagg proves execution capability. It begins with an
approved operating decision, distinguishes two materially different
interventions, exposes the Dagg Factory mechanism, makes permission and a way
back inspectable, and closes by naming the operating choice before release.

The route must not read as an engineering catalogue or a consulting process
deck. Its argument is:

`approved operating decision -> correct intervention mode -> governed Factory build -> permission and verification -> explicit operating choice`

The page has five beats in this exact semantic order:

1. Position;
2. Two intervention modes;
3. Factory;
4. Trust;
5. Operating choice and close.

The content contract fixes every public sentence, label, provenance line,
boundary and destination. Composition may progressively expose the approved
detail assigned to that state, but it may not invent product language, remove a
claim boundary or substitute a visual metaphor for the argument.

## 6. Beat 2 - Two intervention modes

### Exact public copy

**Internal anchor ID**  
`factory-modes`

**H2**  
Automate what should stay. Rebuild what should change.

**Intro**  
Once a build is justified, the first decision is not which model to use. It is
whether a sound workflow needs a bounded agent or automation layer - or whether
the workflow and its software must be rebuilt together.

### Automate what should stay

**H3**  
Keep the workflow. Remove the manual handoffs.

**Body**  
When the workflow is sound but people move information between disconnected
systems, Dagg builds a bounded agent or automation layer around what remains.
The action, permitted tools, exception path and release owner are explicit
before execution.

### Rebuild what should change

**H3**  
Replace the workflow layer.

**Body**  
When the workflow or software preserves the wrong operating model, adding an
agent makes the wrong thing faster. Dagg Factory builds the target workflow as
custom AI-native software, with interfaces, acceptance tests, migration and
reversal defined.

**Text link**  
See the company context behind the build

### Section job

Make the first product decision legible: preserve a sound workflow and remove
its human carrying, or rebuild the workflow layer when the current operating
model is wrong. The reader must not leave with the impression that Dagg wraps
an agent around every process.

The next question is: **Where did the requirements and boundary come from?**
The text link routes to `/workgraph#record`.

### Component and composition

Use `InterventionModeField`, one shared editorial field with two asymmetric
lanes. This is not a pair of equal floating cards and not a feature matrix.

- At desktop, the H2 and intro occupy a 7-column conclusion block. The two mode
  entries follow as one 5/7 or 6/6 comparison separated by a fine rule and
  generous offset, not independent rounded containers.
- Both H3/body blocks are default-visible exactly as accepted.
- A mode may receive focus or selected emphasis, but selection never hides,
  rewrites or replaces the other mode.
- The comparison has no arrows, pipelines, numbered process boxes or icon row.
- One coral mark may identify the operating decision between the modes. It may
  not color both modes or become a decorative underline system.

At 939 px and below, `Automate what should stay` precedes `Rebuild what should
change` in one column. The divider becomes spacing or a full-width rule; the
entries do not become stacked cards.

### Interaction and fallback

V1 may be completely static. If an enhanced mode selector is used, it behaves
as a pressed-button emphasis control, not navigation tabs: both complete mode
arguments remain visible and the selected state changes only one contextual
cue. Pointer, focus and tap are equivalent. Reduced motion swaps emphasis
immediately. Without JavaScript both modes remain complete and the enhancement
control disappears.

### Finite Factory progression

The enhanced pass reuses terms already present in the accepted Factory copy:

`Intervention -> Specification -> Architecture -> Build -> Evaluation -> Governed review`

- The pass starts once when its sentinel enters the upper 60 percent of the
  viewport. It never loops and does not start merely on page load.
- Total duration is 6-8 seconds and then the resolved state holds.
- The intervention/mode decision is a visible judgment hold before the machine
  continues.
- Evaluation is a visible verification hold; it may withhold release and route
  the exception.
- Coral appears only at the judgment hold.
- Sage appears only at the verification boundary and governed resolved state.
- The exact reader controls remain: running `Pause sequence`; paused `Resume
  sequence`; complete `Replay sequence`; reduced motion `Inspect resolved
  progression`.
- Concise live status announces `Judgment hold`, `Verification hold` and
  `Governed review complete` at those three meaningful states.
- With reduced motion the playback controls are replaced by `Inspect resolved
  progression`; activating it keeps the final governed state visible and moves
  focus to the ordered progression without promising animation.
- The user may directly inspect either plan without replaying the full pass.

Machine Signal is restricted to the causal change inside this one instrument:
a short resolution snap, provenance echo or state alignment. It never becomes
an ambient background, particle field, tunnel, glowing scan or second visual
world.

### Plan interaction

The two selectors represent alternate constructed plans, not pages or hidden
marketing tabs. Selecting a plan changes the one coherent detail region and
the finite progression's data. The selected plan is exposed programmatically.
Focus does not jump, the outer carrier does not reflow and hidden detail is not
focusable.

The default state must still expose:

- both plan titles;
- `Evaluation passed. Release remains with the owner.`;
- `Acceptance boundary met. Ready for governed review.`;
- provenance, title, status and constructed-example disclosure.

### One capability, two surfaces — deferred interaction

FS5 keeps this as exact explanatory copy attached to the rebuilt-plan example,
not a second hero, toggle or interface theatre. The same company context,
permission, owner and record remain the stated invariants. Do not use a vendor
logo, branded chat chrome, fake prompt, named customer or fabricated query
result. FS6 may add one bounded coded carrier only after the P4R5 two-surface
contract, migration ownership and evidence boundary are reconciled.

### Reduced motion and no JavaScript

With `prefers-reduced-motion: reduce`, no automatic sequence is scheduled and
all Factory motion durations compute to 0 ms. The selected plan appears in its
complete resolved state immediately with judgment, verification, owner and way
back intact. Controls use inspect language; no label promises motion that will
not occur.

Without JavaScript, both plans render in semantic order as complete records.
All rows, both resolved states, the dual-surface body and boundary are readable.
Enhanced selectors, pause and replay controls disappear. The ordered progression
is rendered as an ordinary list and the same governed review outcome remains.

## 13. Motion, reduced motion and no-JavaScript truth

### Normal motion

Only one narrative event is permitted: the sentinel-started Factory pass. The
6-8 second pass starts once when its sentinel enters the upper 60 percent of the
viewport, has a visible judgment hold, verification hold and resolved state,
then stops. Hover or focus within the existing interactive carrier pauses it;
leaving resumes only that suspension source. Plan/state changes use 220-300 ms;
UI responses use 120-180 ms; Machine Signal resolution uses 0.8-1.2 seconds
within the pass. There is no looping narrative, autoplay hero, ambient loop,
parallax, fake typing or moving background.

Only one narrative event moves in a viewport. Pause and replay are direct,
labelled controls with visible focus. Orientation change or resize preserves
the selected plan and resolved meaning without restarting motion.

### Reduced motion

- the Factory sequence does not schedule a timer and resolves immediately;
- transition and animation durations compute to 0 ms;
- the selected plan opens in the same governed resolved state;
- judgment, verification, owner, boundary and way back remain explicit;
- page geometry, copy assignment and destinations are unchanged;
- no control promises playback when the experience is an immediate state swap.

### No JavaScript

- exactly five Build beats and one H1 remain;
- both intervention-mode arguments remain complete;
- both Factory plans, every row, both resolved states and the dual-surface
  boundary are readable in order;
- the Factory progression is an ordinary ordered list;
- no inert selector, pause, replay, tab, empty panel or hidden state remains;
- all routes and anchor links remain ordinary links;
- Impact remains atomically absent while gated;
- disclosure, provenance, owner, permission and way back remain visible.

No critical fact is hover-only, motion-only, color-only or JavaScript-owned.

## 14. Accessibility contract

- One header, one main and one footer occur in order; there is exactly one H1.

  are at least 48 x 48 px.

  closes it and restores focus to the disclosure button. The mobile sheet
