## 1. Page decision

**FS5 amendment.** The hero is now a 5/7 product-mechanism split: proposition
left, coded WG-034 record right. The page disclosure precedes the record.
Decision, Owner and Permission are default-visible; Evidence, Operating state,
Reason, Provenance and History live under `Provenance and history`. The existing
Decision Field image moves to Context in section 2. Lifecycle paragraph one
remains default-visible; paragraph two moves under `Why the record persists`.
Default copy is ≤430 words. At 390×844
the record identity, Owner and Permission begin within the first viewport.

FS5 supersedes every instruction below that places the Decision Field image in
the hero. The position hero is a 5/7 proposition-and-record composition. The
coded WG-034 record, not the Decision Field image, owns the hero. WG-DF-OE-01
moves to Context in section 2. At 390×844, record identity, current state and
Owner or Permission begin within the first viewport.

WorkGraph is a central Dagg technology, not a decorative process map and not
the whole Dagg proposition. The route must make one thing concrete:

> company context can remain usable across transformation, Factory builds and
> ongoing operating decisions even as models, workflows and systems change.

The page therefore has one warm conceptual world and one inspectable product
artifact:

1. **Decision Field** establishes how scattered operating reality becomes a
   coherent, governed company record.
2. **Operational Evidence** makes one retained record inspectable as a real
   coded component.

Machine Signal is not used on this route. The Image Language production map
assigns WorkGraph `Decision Field + Operational Evidence`; adding Machine
Signal would create an unauthorized third language. Ordinary micro-response is
allowed, but it may not become a scan, resolution effect or ambient machine
world.

The argument has five fixed acts:

1. Position;
2. Context and retained record;
3. Lifecycle;
4. Control and proportionality;
5. Build bridge and next move.

The reader should leave with this sequence:

`operating reality -> retained record -> reusable company context -> explicit boundary -> governed build`

### Component: `RetainedWorkGraphRecord`

Use one semantic `<article>` inside a single 14 px Ink instrument. It has four
uninterrupted regions separated by hairlines, not floating cards:

1. **Identity.** Provenance, `WG-034 · Supplier payment exception` and
   `Decision retained` remain fixed.
2. **Operating truth.** Evidence and Operating state.
3. **Judgment and control.** Decision, Owner and Permission.
4. **Retained depth.** Reason, Provenance and History.

The default view shows regions 1-3. Region 4 uses one native disclosure whose
visible summary is `Provenance and history`. The disclosure contains the exact
progressive copy in its accepted order. Without JavaScript it remains a native,
operable detail.

Use a semantic `<dl>` for individual fields and an ordered list for History.
JetBrains Mono is limited to the record ID, status and provenance labels. Field
values use the normal reading type; the artifact may not look like code.

### Source-lens interaction

The component progressively enhances three ordinary text buttons derived from
the accepted Provenance field:

- Meeting;
- Document;
- System state.

The buttons form a labelled pressed-button group. Selecting a source does not
hide, replace or rewrite any record field. It only makes the source's
contribution inspectable:

| Source lens | Fields emphasized | Meaning |
|---|---|---|
| Meeting | Decision, Reason and Owner | Human judgment and accountability enter the record |
| Document | Evidence and Reason | A source discrepancy supplies the basis |
| System state | Operating state and Permission | The current state and allowed action remain explicit |

This relationship is a constructed interaction inside the disclosed synthetic
record. It is not a claim about a named client integration.

The outer instrument, record identity, status and all fields remain stationary.
Selection uses Ink structure, weight and focus; Coral is reserved for the
Decision row, not the active button. Sage is reserved for Permission and the
withheld state.

The selected button uses `aria-pressed`. A concise polite status announces the
contract's exact state: `Meeting source highlights the fields retained from
that source`, `Document source highlights the fields retained from that
source` or `System state source highlights operating state and permission`; it
must not repeat the entire record. Hidden or de-emphasized content is never
removed from the accessibility tree.

The initial source state is authored in HTML: `Meeting` has
`aria-pressed="true"` and the static status is `Meeting source highlights the
fields retained from that source`. JavaScript must not rewrite or announce that
state on load. It changes the pressed lens, emphasis and status only after an
actual pointer, keyboard or touch selection.

### Why this is Operational Evidence

The record has stable identity, exact synthetic content, provenance,
permission, human judgment and returned evidence. The reader changes one lens
and can inspect the consequence. It is therefore a product mechanism, not a
photograph pretending to be proof.

Do not substitute:

- a node-edge graph;
- a workflow diagram;
- a dashboard with metric tiles;
- a terminal, code window or fake chat;
- a generated pseudo-interface;
- multiple card panes or one panel per field;
- a cinematic Operational Evidence bitmap.

### Motion and state response

Source selection uses a 220-300 ms emphasis change with no overshoot, travel or
outer-layout change. The interaction is reader-triggered and then still. It is
not Machine Signal.

Reduced motion changes the emphasized fields immediately. No-JavaScript hides
the inert source controls and displays the complete record plus the native
`Provenance and history` disclosure. The page disclosure and local provenance
remain visible in every mode and viewport.

## 15. Motion, reduced motion and no-JavaScript truth

### Normal motion

The page has no autoplay narrative event. The Context still uses one finite
editorial settle after its section enters view. Only the retained-record source lens changes
meaningful state. Its response is 220-300 ms and then still. Link, focus and
disclosure responses stay within 120-180 ms.

There is no:

- ambient background motion;
- hero loop;
- Machine Signal scan;
- scroll-driven record construction;
- fake typing;
- animated node graph;
- parallax or pinned storytelling;
- automatic lifecycle progression.

### Reduced motion

Under `prefers-reduced-motion: reduce`:

- source emphasis and disclosures resolve immediately;
- route-specific transition and animation durations compute to 0 ms;
- the same selected source, record fields, provenance, permission and history
  remain available;
- geometry, order and copy are content-equivalent to normal motion.

### No JavaScript

Without JavaScript:

- all five acts, one H1 and the complete ordered argument remain;
- all record fields, provenance and History remain available;
- the `Provenance and history`, `Lifecycle states` and `Technical diligence`
  disclosures use native semantics;
- inert source-lens controls are absent;
- every page-local and global destination remains an ordinary link;
- no empty panel, `aria-hidden` claim, placeholder, warning screen or script-
  dependent route remains;
- the Context still and retained record have intrinsic dimensions and stable
  content.
