# Dagg Image Production Protocol

Status: binding production companion to `Dagg-Image-Language-System.pdf`  
Owner: Codex image direction and generation lane  
Consumers: Codex and Claude Home cuts, component library and later page builds

## 1. Existing images are exemplars, not the complete library

The approved PDF establishes three visual roles. The current repository holds a
seed portfolio for each role: six still candidates and one motion storyboard,
plus a small set of hero explorations. These assets prove the grammar; they are
not a fixed menu and they do not complete the production inventory.

The library grows from actual narrative slots. Do not bulk-generate decorative
inventory merely to reach an asset count.

## 2. The three roles

- **Decision Field** is the surrounding world: strategy, context, judgment and
  the operating model becoming legible.
- **Operational Evidence** is contained proof: a named state, record,
  consequence, provenance and truth boundary. A generated concept image may
  carry this role, but it must never be captioned as a live product or client
  result. Where the proof is interactive, build it as real HTML.
- **Machine Signal** is a finite state change between coarse and resolved. It is
  normally a before/after pair or short controlled transition, not ambient art.

The 70/25/5 balance applies to composed full pages, not the raw catalog. One
section never uses all three roles. Home hero uses Decision Field plus a
restrained Machine Signal; Operational Evidence appears later as proof.

## 3. Slot-first production

Every major image begins with a frozen slot brief:

1. route and section;
2. narrative claim and causal event;
3. visual role;
4. adjacent copy and interaction;
5. measured desktop and mobile carriers;
6. required quiet field and focal position;
7. what coral changes and what sage governs;
8. protected subject for every crop;
9. motion start/resolved states;
10. truth boundary and prohibited interpretations.

Codex ImageGen produces three to four candidates for a major slot. A visual
judge accepts one, asks for one targeted iteration or rejects the family. Final
desktop and mobile images are art-directed separately; mobile is never a blind
center crop.

## 4. Shared asset lane for independent cuts

Codex and Claude do not operate separate image generators.

- Both `X0` implementations receive the same approved asset registry.
- Claude may request a slot brief but may not invent a parallel visual language.
- Codex's image lane generates and records candidates without changing the
  builder's narrative or layout.
- Each implementation may choose and compose approved candidates differently.
- Cross-review identifies the best image, crop, motion and relationship to copy.
- Only assets used by a verified `X1` or a later page remain production-approved.

This keeps the Codex and Claude cuts independent in composition while giving
both equal access to the highest-quality image generation.

## 5. Asset record

Every candidate and approved asset records:

- stable asset ID and version;
- role: Decision Field / Operational Evidence / Machine Signal;
- intended route, section and carrier;
- narrative event;
- source prompt and reference assets;
- native dimensions, format and hash;
- desktop and mobile art direction;
- protected focal event;
- motion pair or resolved frame, if applicable;
- alt/figcaption treatment;
- provenance and truth boundary;
- status: exemplar / candidate / approved / assigned / rejected / retired.

One image has one primary narrative job. Reuse is allowed only when the same
causal event is being recalled deliberately; convenience is not a reason.

## 7. Rejection conditions

Reject an asset when it:

- requires a caption to create meaning that is absent from the image;
- could belong to a design studio, generic AI company or another peer;
- uses coral or sage decoratively;
- introduces a circuit board, node cloud, terminal, dashboard, brain, robot,
  neon field, decorative particles or generic chat UI;
- shows all three roles at once;
- does not fit the measured carrier or loses the event on mobile;
- implies live product, customer evidence, security assurance or production
  performance without its own evidence.
