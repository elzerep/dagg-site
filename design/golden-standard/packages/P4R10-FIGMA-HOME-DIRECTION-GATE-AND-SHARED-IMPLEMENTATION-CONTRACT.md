## 5. Shared component contract

These rules survive the A/B/C choice.

### Global chrome

- Use the real Dagg logo asset. No typed substitute, hand-drawn mark or fake
  icon.
- Desktop header target: 72 px, visually quiet and structurally precise.
- Direct routes: `Transformation`, `WorkGraph`, `Company` and
  `Start an assessment`. Build is the named native disclosure described below;
  its first destination is the real Build overview link.
- `Impact` is omitted atomically until publishable evidence and a live route are
  approved. It is never shown disabled.
- Every label is a real route. Ordinary internal routes stay in the same tab.
- The assessment action remains visible and reachable in every navigation mode.

### Adaptive Build preview

- FS5 uses the existing native `<details><summary>` disclosure named `Build`.
  The summary owns expanded state; the first item inside is the real Build
  overview link. FS6 migrates this to a split overview link plus adjacent named
  disclosure button after parity is proven.
- Desktop fine pointer opens after 70–100 ms of intent and closes 180–240 ms
  after leaving both trigger and panel.
- Preview emphasis responds in approximately 120 ms; content crossfades in
  100–140 ms; bounded inset morph may use 180–240 ms. No overshoot, reflow or
  outer-panel jump.
- Keyboard: Enter or Space opens; Tab reaches every destination; Escape closes
  and returns focus to the disclosure control.
- Touch: one-at-a-time disclosure with the same real destinations. Mobile uses
  a reading sheet, keeps the background inert and restores focus to the opener.
- Reduced motion removes position, scale and size morph. The selected state
  swaps immediately or with a brief opacity change.
- No JavaScript preserves top-level links and every Build destination through a
  static fallback described below.

#### Required destinations and preview states

| Destination | URL | Required preview conclusion |
|---|---|---|
| Build overview | `/build` | One operating decision becomes a buildable, governed system. |
| Dagg Factory | `/build#factory` | Context and decision remain attached through design, architecture, build and evaluation. |
| Agents and software | `/build#factory-modes` | The intervention follows the operating decision: agent, rebuilt workflow or custom software. |
| Trust and operation | `/trust` | Authority stops at the named boundary; ownership, evidence and way back remain explicit. |

Pointer hover and keyboard focus on each destination expose the same preview
state. Touch selection exposes the same content in the reading sheet. The outer
flyout box, trigger location and route list remain fixed; only the bounded proof
inset changes.

#### Required DOM and focus contract

- In FS5, `Build` is a native `<summary>` inside one `<details>` disclosure. The
  first destination is a real `<a href="/build">Build overview</a>`.
- DOM focus order is Build summary → destination links → any labelled close
  control → next global route.
- Enter and Space on the summary toggle the disclosure. Escape closes it and
  restores focus to that same summary.
- The mobile reading sheet contains focus while open; the page below is
  `inert`; closing by Escape, backdrop or labelled close control restores focus
  to the opener.
- Hidden preview states are neither exposed nor focusable.

#### Deterministic capability matrix

| Environment | Required mode |
|---|---|
| Width ≥1024, `(hover: hover)` and `(pointer: fine)` | Desktop flyout for pointer and keyboard. |
| Width ≥1024, `(any-hover: hover)` and `(any-pointer: fine)` on a hybrid device | Mouse/trackpad and keyboard use the flyout; an event whose `pointerType` is `touch` or `pen` opens the reading sheet. |
| Width <1024, regardless of keyboard presence | Reading sheet/disclosure; keyboard operates the same control and destinations. |
| Coarse-pointer-only environment at any width | Reading sheet/disclosure. |
| JavaScript disabled | The native Build `<details><summary>` remains operable and exposes `/build`, `/build#factory`, `/build#factory-modes` and `/trust`. Enhancement-only controls are absent or inert-free. |

### Typography, controls and icon discipline

- Public type floor: 12 px. Do not use smaller copy to force a composition.
- Desktop interactive target: at least 44 × 44 px. Touch target: at least
  48 × 48 px.
- Home hero and strategic editorial sections use zero icons.
- Product proof normally uses zero to two semantic marks only when ownership,
  boundary, evidence or state would otherwise be ambiguous.
- Use familiar licensed utility icons for disclosure, close, external
  destination, play, pause or replay. No decorative icon rows or feature-icon
  factory.
- Cards are not a default container. Use surfaces only when they clarify
  hierarchy, state or interaction.

## 6. Image-language contract

Home remains **Decision Field primary with restrained Machine Signal support**.
Operational Evidence is the coded, inspectable execution artifact; it is not a
third generated-image world spread across the page.

- Act 1 establishes the Dagg world through Decision Field. Machine Signal may
  express one finite resolution and then stop.
- Acts 2 and 6 may be image-free. Whitespace must be authored, not empty.
- Acts 3–5 culminate in one required connected execution object. It must show retained
  context, permission, accountable ownership and returned evidence.
- A section uses at most two image-language roles.
- Never use circuit-board lines, particle wallpaper, terminals, fake chat,
  node maps, dashboards or synthetic biological forms.
- Reject any form that reads as sperm, egg, embryo or fertilisation.
- Mobile and tablet compositions are authored for their slots. Desktop crops
  are not acceptable substitutes.

## 7. Direction-specific behaviour

### A — Editorial Cinematic

- The Ink-to-material hero is one scenographic composition, not an image card.
- Motion is finite and authored: causal reveal at meaningful thresholds, then
  stillness.
- Core copy is never reveal-gated.
- Product proof resolves once and remains inspectable.
- Reduced motion shows the complete resolved composition immediately.

### B — Intelligent Instrument

- One physical proof carrier remains coherent while the narrative advances.
- Scroll updates the carrier through complete named states; it never traps,
  snaps or hijacks the page.
- State changes context, recommendation or action, permission and evidence as a
  coordinated unit.
- Mobile removes stickiness and presents every state in complete document
  order.
- Reduced motion removes stickiness, scroll-linked transforms and carrier
  morph. It renders all four complete states in semantic document order with no
  waiting timers. A bounded opacity change is the only optional transition.

### C — Sovereign Systems Story

- One wide film field carries four authored frames: retained record, boundary
  and owner, governed build, evidence return.
- The camera and visual world remain coherent; motion is finite and causal.
- The film may pin briefly but never lock or snap the reader.
- Reduced motion lands directly on frame 04 with all causal labels available.

## 13. Stop conditions

Stop and report rather than improvise if:

- exact copy cannot fit without violating the type or density floor;
- a required responsive composition needs an unapproved image crop or asset;
- the shared component layer prevents correct semantics, focus or touch
  behaviour;
- a builder would need to edit outside its owned files;
- an interaction hides the central story from reduced-motion, keyboard,
  touch or no-JavaScript readers;
- evidence cannot prove which exact build was inspected;
- a visual claim implies a client deployment, provider, managed operation or
  quantified outcome that has not passed the publication gate.

No publication, deployment or production replacement is authorized.
